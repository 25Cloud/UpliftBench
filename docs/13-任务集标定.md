## 二、两个必须写下来的发现

### 1. 「设计难度」和「实测难度」几乎不相关

我在设计阶段按「改几个点、要不要跨文件」估的难度，实测下来几乎全部落空：
标为 hard 的 8 个任务里，有 4 个 baseline 直接 100%；标为 medium 的 13 个里，有 9 个 100%。

**结论：难度不能靠设计者自评，只能靠实测。** 这也正是 `docs/04 §6` 第 4 条准入检查要存在的原因——
只是它以前是个「需要真跑」的空条款，现在有了第一个实测数字。

### 2. 单文件模式替换类任务呈**双峰分布**，没有中间地带

30 个任务的实测结果只有两种：100% 或 0%。**没有一个是 30–70%。**

原因不难解释：这类任务对模型是「知道这个 API 就一次做对，不知道就完全做不对」，
不存在「做了一半」的中间态。而 `docs/04 §5.2` 想要的「medium 占 40–50% 的甜点区」，
在模式替换类任务上根本不存在。

**这对任务集设计的含义**：想要连续难度分布，任务必须包含**可部分完成**的成分
（多文件、多规则、有互相冲突的约束），而不是单点替换。这是一个真实的、可执行的设计结论。

## 三、怎么复现标定

```bash
export UPLIFT_API_KEY=... UPLIFT_MODEL=glm-5.3-flash
node dist/cli.js run \
  --taskset web-guidance@1.0 \
  --skill benchmarks/skills/modern-web-guidance-src/.agents/skills \
  --arms baseline --repeats 1 --jobs 6 --out .uplift/calib

# 把实测结果写成标定文件，再重跑生成器（会回填 expected_baseline）
node tools/calibrate-web-guidance.mjs      # 见脚本
pnpm gen:web --commit=$(git rev-parse HEAD)
```

> 注意：标定用的技能包只是提供 `skill_commit` 与展示名，baseline 臂不装任何技能，
> 所以换哪个技能包都不影响 baseline 数字。

## 四、重新标定（2026-11-13 · web-guidance@1.3.0 · 58 题）

v1.0 那份标定是 **1 repeat、30 题**——样本太少，而且新加的题压根没标。
现在用第二轮那 720 次 run 里的 baseline 臂（**每任务 5 次采样**）重新标了一遍，
再加上新题的标定库，58 题全覆盖：

```bash
node tools/calibrate-web-guidance.mjs \
  --db=.uplift/v11/runs.db,.uplift/calib-2/runs.db,.uplift/ablation/runs.db,.uplift/ablation3/runs.db \
  --domain=web-guidance
node tools/calibration-report.mjs        # 看难度分布与天花板占比
pnpm gen:web
```

结果：

| 难度档 | 题数 | 占比 |
|---|---|---|
| 100%（天花板） | 35 | 60% |
| 50–99% | 11 | 19% |
| 1–49% | 5 | 9% |
| 0% | 7 | 12% |

**天花板比例从 73%（30 题版）降到 60%，加了 10 道题只换来 13 个百分点。**
新加的 10 道题里 8 道最终还是 100%——因为我把 API 名字写进了提示词，它们成了转写题。
这个失败的详细分析在 `docs/16-消融实验.md`，那里也给出了下一轮的选题判据。

两个以前踩过的坑，这次写进脚本了：

1. 老版 `calibrate-web-guidance.mjs` **不筛 arm**——库里同时有三臂时，会把 treatment 的
   `pass` 当成 baseline 写进标定。现在固定 `where arm = ?`。
2. 老版 `samples` 恒为 1——多 repeat 的库被当成一次采样，均值信息全丢。现在按任务聚合，
   `samples` 记真实样本数，`--min-samples` 可以踢掉样本不足的题。

### 多库合并

标定源常常不止一份库（第二轮 720 次 run 一份、新题标定一份、消融实验一份）。
`--db=a.db,b.db,…` 现在是**把同一个任务的样本合到一起算均值**，不是后写的覆盖前写的：
每一个 run 都是一次独立观测，丢掉一半样本只会让 `expected_baseline` 更抖。

```bash
node tools/calibrate-web-guidance.mjs \
  --db=.uplift/v11/runs.db,.uplift/calib-2/runs.db,.uplift/ablation/runs.db,.uplift/ablation3/runs.db
```
