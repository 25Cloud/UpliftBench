# 14 · 首轮实测（v0.1）

> 这一份是**真实跑出来的数字**，不是示意。原始记录：`.uplift/main/runs.db`（270 行）。
> 所有数字都带 N 与置信区间；没有置信区间的数字在这里不作结论用。

| 项 | 值 |

## 二、结果

| 臂 | 通过率 | 跨重复标准差 |
|---|---|---|
| baseline（不装） | **78.89%** | 0.0509 |
| placebo（等量中性文本） | **74.44%** | 0.0385 |
| treatment（真技能） | **76.67%** | 0.0333 |

```
uplift          +2.22pp   （treatment − placebo）
headroom        8.7%      ← 只剩这么点空间可填
raw_gain        −2.22pp   （treatment − baseline，未校正）
placebo_effect  −4.44pp   （placebo − baseline）
95% CI          [−2.22, +6.69]   → 跨 0，不显著
N               30        A 级
```

### 结论（严格版）

**在这个任务集、这个模型上，这个技能包的可测量净增益是 +2.2pp，95% CI 跨 0，无法与「没有效果」区分。**

能说的：它没有害，也没有可测出的帮助。
不能说的：它没用（一个任务集、一个模型、一个包，不够下这个结论）。

## 三、本轮最有价值的一个数字：口径会把符号搞反

同一批 270 次 run，只换算法：

| 口径 | 公式 | 结果 | 会得出什么结论 |
|---|---|---|---|
| 两臂（业界通行） | treatment − baseline | **−2.22pp** | 「装了它反而变差」 |
| 三臂（本协议） | treatment − placebo | **+2.22pp** | 「轻微正增益，但不显著」 |

**两个数字的差 = 安慰剂效应 = −4.44pp，比技能本身的效应还大。**

也就是说：在这批数据上，**两臂口径给出的符号是错的**。
原因不是技能有害，而是「往上下文里塞 100k token 的技能包」这件事本身让通过率降了 4.4pp。

这正是 `docs/00-WHY.md §六` 声称的东西，现在有了第一组实测支持。

**必须一起说的分寸**：每臂 90 个 run，`p≈0.77` 时单臂标准误约 **4.4pp**。
-4.44pp 的安慰剂效应正好在 1 个标准误量级上，**它本身也不显著**。
所以严格的说法是：**安慰剂项与效应项同量级，足以改变结论的符号，但这一轮还不足以下显著性断言。**
要压窄到能做判断，需要把 `repeats` 提到 5、把任务数提到 60 以上。

真正能压窄方差的是配对 bootstrap（按任务配对），也就是上面那个 `[-2.22, +6.69]`。

## 四、代价类数字（技能包真正的成本）

| 指标 | 值 | 说明 |
|---|---|---|
| 包内 token 合计 | 102,303 | 25 个技能 |
| 最大的单个技能 | **10,255 tok** | 已超 10k 注入预算 2.5% |
| 输入 token 增幅 | **+445.8%** | treatment 相对 baseline 的输入 token |
| 输出 token 合计 | 32,759 | |
| 工具调用均值 | 4.72 / run | |
| 稳定性增益 | +0.018 | baseline 标准差 − treatment 标准差（正数=更稳） |
| flaky 任务 | 5 个（wmg-011/017/027/029/030） | 同臂内跨重复结果不一致 |

**+445.8% 的输入 token 增幅**是容易被忽略的一栏：装一个 25 技能包，每轮对话的输入侧成本是原来的 5 倍多，
而换来的净增益是 +2.2pp（不显著）。这个对比本身就是「值不值得装」的答案。

## 六、已知局限（读这些数字时必须一起读）

1. **一个任务集、一个模型、一个技能包**。任何排名结论都不成立。
2. `repeats=3`，`docs/11 Q2` 的默认值是「≥5 才报 CI」——这里的 CI 只作参考宽度看，不作显著性判据。
3. 任务集本身呈双峰分布（见 `docs/13`），因此 baseline 78.89% 意味着**天花板只剩 21pp**，
   且 30 题里 22 题 baseline 就是 100%，它们对 uplift 没有任何贡献能力。
4. 成本口径用端点返回的 `usage.credit` 累加，不是官方价格表折算。
5. `agent-skills` 是通用工程技能集，不是 Web API 迁移专精——这一配对更像「通用技能能否顺带提升迁移任务」，
   而不是「它的主场表现」。`docs/04 §3.3` 说的「交题即声明」在这里没有被满足：
   我没能让它自己的作者交一套任务集。
