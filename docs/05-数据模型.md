### 字段约束

| 字段 | 约束 |
|---|---|
| `schema_version` | 固定 `1.0.0` |
| `protocol_version` | 必须存在，用于历史可比性 |
| `skill.commit` | 必填，40 位 sha |
| `tier1.metrics.uplift_pp` | **必须等于 `treatment − placebo`**，不是 `− baseline` |
| `tier1.metrics.placebo_effect_pp` | 必填，不可省 |
| `tier1.ci95` | 必填，数组 `[low, high]` |
| `tier1.grader_tier` | `A`/`B`/`C`，与 taskset 一致 |
| `tier1.n` | 必填；`< 30` 时 `verdict.grade` 最高为 `B` |
| `tier0` | 若某探针 `supported: false`，该键必须存在且含 `{"supported": false, "reason": "..."}` |

## 三、运行记录（`runs` 表，SQLite）

```sql
CREATE TABLE runs (
  id            TEXT PRIMARY KEY,      -- uuid
  skill_repo    TEXT NOT NULL,
  skill_commit  TEXT NOT NULL,
  taskset       TEXT NOT NULL,         -- "web-guidance@1.0"
  arm           TEXT NOT NULL,         -- baseline|placebo|treatment
  task_id       TEXT NOT NULL,
  repeat_idx    INTEGER NOT NULL,
  model         TEXT NOT NULL,         -- 精确版本
  harness       TEXT NOT NULL,
  temperature   REAL,
  seed          INTEGER,
  started_at    TEXT NOT NULL,
  ended_at      TEXT NOT NULL,
  pass          INTEGER,               -- 0/1, NULL 表示 grader_error
  failure_kind  TEXT,                  -- 见协议 §3.4
  tokens_in     INTEGER,
  tokens_out    INTEGER,
  tool_calls    INTEGER,
  wall_ms       INTEGER,
  cost_usd      REAL,
  transcript_path TEXT,
  meta_json     TEXT
);

CREATE INDEX idx_runs_skill ON runs(skill_repo, skill_commit);
CREATE INDEX idx_runs_taskset ON runs(taskset, arm);
```

**设计要点**：
- 一行 = 一个 (臂, 任务, 重复) 组合，**不聚合**。聚合在查询时算。
- `transcript_path` 指向完整轨迹文件，便于事后审计。
- `pass` 用 `NULL` 区分「失败」和「评分器错误」。

## 四、聚合视图

```sql
CREATE VIEW v_arm_stats AS
SELECT skill_repo, skill_commit, taskset, arm,
       AVG(CASE WHEN pass IS NULL THEN NULL ELSE pass END) AS pass_rate,
       COUNT(*) AS n_runs,
       COUNT(DISTINCT task_id) AS n_tasks
FROM runs
WHERE pass IS NOT NULL
GROUP BY skill_repo, skill_commit, taskset, arm;
```

## 五、Badge SVG 规格

### 5.1 完整版（榜单页用）

```
uplift 31% (base 40 → treat 76, placebo 45) A级
```

### 5.2 精简版（README 用，≤ 12 字符）

```
uplift 31%
```

**颜色规则**：
| uplift_pp | 颜色 |
|---|---|
| ≥ +15 | 亮绿 `#2ea44f` |
| +5 ~ +15 | 绿 `#4c9a2a` |
| 0 ~ +5 | 灰 `#9e9e9e` |
| < 0 | 红 `#d73a49` |

**`placebo_effect_pp > uplift_pp` 时强制加 `⚠️` 角标**，这是「分数主要来自长度」的信号。

### 5.3 悬停信息（SVG `<title>`）

```
UpliftBench · web-guidance@1.0 · A级
uplift +31pp (headroom 56%), N=30, 95%CI [22, 40]
placebo effect +5pp, baseline 40%, treatment 76%
Protocol protocol/1.0.0 · 2026-11-13
```

## 六、文件布局（仓库内）

```
.uplift/
├─ skillcard.json          # 主结果
├─ runs.db                 # SQLite 原始记录
├─ transcripts/
│  └─ <task_id>/<arm>/<repeat>.jsonl
└─ badge.svg
```

**`.uplift/` 应加入 `.gitignore`**，但 `skillcard.json` 和 `badge.svg` 建议提交（供 CI 校验）。
