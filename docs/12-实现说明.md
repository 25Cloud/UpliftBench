## 一、技术栈落地

| 项 | 文档要求 | 实际实现 |
|---|---|---|
| 语言 | TypeScript / Node 22+ | ✅ Node 22.22，`tsc` 编译到 `dist/`，ESM |
| CLI 框架 | commander 或 cac | ✅ `commander@12` |
| 存储 | better-sqlite3 | ✅ `better-sqlite3@11.10`（本机无预编译包，走 node-gyp 源码编译通过） |
| 隔离 | git worktree + 子进程 | ✅ 每个任务一个极小 git 仓库，worker 从它 `worktree add` 出干净树 |
| 测试 | vitest | ✅ 54 个用例 |
| 榜单页 | 静态生成 | ✅ 纯 HTML（`uplift site`），不引构建器 |

**为什么每个任务单独 init 一个 git 仓库**：一个任务的 workspace 应该是任务集的 `fixture/`，而不是 UpliftBench 的源码树。把 fixture 提交成一次性仓库后，`git worktree add` 出的每份树天然干净，重置只要 `reset --hard` + `clean -fdx`。

## 二、按默认值实现、待确认的 6 处

### 1. token 计数系数（docs/03 与 docs/11 Q5 有出入）

- `docs/03`：英文 `chars/3.6`
- `docs/11 Q5`：英文 `chars/4`、中文 `chars/1.7`、混排加权

**实现**：按 `docs/11 Q5`，输出字段固定为 `tokenizer: "approx:weighted"`。
理由：Q5 是后写的收敛结论，且加权对中英混排更稳。**这不是协议字段，属于 MINOR 级实现细节。**

### 2. 评分器版本槽位

`AGENTS.md §1` 硬约束要求 `taskset.json` 锁定「评分器版本」，但 `schema/taskset.schema.json` 里没有这个字段。

**实现**：`grader.version` 作为**可选**字段加入（MINOR 变更，已是 schema 现状）。老任务集不带这个字段仍然合法。

### 3. `env.kind: "local"` 与 digest 检查的冲突

schema 允许 `local`，准入检查第 5 条却要求 `image_digest` 非空。

**实现**：`kind=local` 时跳过 digest 检查，打 `env_unpinned` 标记并在 validate 输出里显示 ⚠️。
非 docker 环境下强行编一个 sha256 是造假，不如显式标注。

### 4. 退出码 3 与「5 个包都出卡」的张力

`docs/06` 规定有探针 `supported:false` 时退出码 3，而 D7 的验收是「5 个包都出卡」。

**实现**：卡照出（写入磁盘），退出码仍然返回 3。CI 判「有卡即过」，退出码只进日志。
理由：退出码是给脚本用的信号，不该被「反正卡出来了」掩盖。

### 5. 三份输入文件的格式（文档未定义）

- `triggers.json`：`{positive: [...], negative: [...]}`，元素可以是字符串，也可以是 `{prompt, kind}`，
  `kind ∈ unrelated | adjacent | same_domain`（对应 `docs/11 Q6` 的三档负样本）
- 注入语料：**内置 12 条**（`src/probes/injection-resistance.ts` 的 `INJECTION_CASES`），不做外部文件
- `--general-tasks`：直接复用任务集格式（`tasksets/general-20`），不另造一套 schema

### 6. 安慰剂「结构相似」的匹配程度

`docs/02 §1.2` 要求结构相似，`docs/11 Q1` 默认值说只匹配总 token 数。

**实现**：折中方案 —— **逐技能**生成安慰剂（每个技能一份，token 逐个对齐），文本自带 `#` / `##` 标题与列表。
理由：技能包的真实行为是「激活某一个技能」，激活成本按技能计。生成一大坨总长相同的文本会让安慰剂臂的**激活成本**与真实臂不同，那就不是安慰剂，而是另一种干预。

种子语料目前是 **145 段手写的通用工程叙述（3,826 token）**，
`src/placebo/generate.ts` 按内容哈希洗牌 + 连接句 + 标题分节，再用二分收敛到目标 token 数。
目标长度超过种子长度时会循环复用段落——这是已知局限，见 §四。

## 三、实现上的关键取舍

### 3.1 「技能被激活」是一个真实事件，不是猜的

`openai-compat` harness 自己掌控 agent loop，所以把激活做成**显式工具调用** `activate_skill(name)`：
技能在系统提示里只出现「名字 + 描述」，正文只有在调用工具时才注入上下文。

这带来两个好处：

1. 探针 2（触发精度）拿到的是真实事件流，不是事后猜测；
2. 三臂的注入成本天然对称——baseline 没目录，placebo 有等量中性目录，treatment 有真技能目录。

`claude-code` 适配器反过来：读 `UPLIFT_CLAUDE_HOOK_LOG` 的 jsonl 新增部分，读不到就把 `supportsActivationEvents` 置 false，
探针 2 直接报 `supported:false`。**不编数字**是这条的底线。

### 3.2 三臂交错的实现方式

`buildSchedule()` 先对每个臂用「seed + 臂偏移 + 轮次」洗牌任务，再按 (轮次 × 位置 × 臂) 轮转输出。
效果就是 `b,a,c,a,b,c…`，同时每臂内部任务顺序独立随机。单元测试锁死了三条性质：前三个 unit 覆盖三臂、无重复 unit、同 seed 完全可复现。

### 3.3 grader_error 与 pass 的分离

`pass` 列用 `NULL` 表示评分器自身出错，`failure_kind='grader_error'`。
聚合时 `AVG(pass)` 自动忽略 NULL，所以 `pass_rate` 里不会混进评分器故障。这是协议 §3.4 的硬要求，也是「基准作弊最常见的方式」的防线。

### 3.4 成本记账

优先用端点返回的 `usage.credit`（本次调用实际扣了多少额度）；没有就按公开价目表折算；两者都没有就标 `unpriced` 并把 `cost_usd` 记 0。
**不猜美元数字**——`docs/02 §3.2` 的 cost 字段要能对账。

## 四、已知局限（v0.1 明说不做）

| 局限 | 原因 | 影响 |
|---|---|---|
| 组合技能不测（Q4） | 交互效应无法单包拆分 | 单包数字不能相加 |
| 安慰剂种子语料只有 3.8k token | 手写语料要保证「语义中性 + 语言自然」，不能靠随机词堆 | 目标长度超过种子时段落会循环复用；单技能 >5k token 的包里会有重复段落 |
| `visual-diff` 需要可选依赖 | 不给 A 级用户强装像素库 | 没装时报 `grader_error`，不伪装通过 |
| 负迁移默认只跑 8 题 | 控成本 | CI 偏宽，报告里 `n` 会说话 |
| 卸载探针只做文件级 | 行为指纹要整轮三臂 | `residual_delta_pp` 报 `null` |
| `taskset fetch` 未实现 | 远程 registry 在阶段 3 | 命令返回退出码 3 并说明 |
| 触发精度依赖自建 catalog | 真实 harness 的触发逻辑各不相同 | 跨 harness 的 P/R 不可直接比较 |
| 安装未隔离 `~/.claude` 之外的全局写 | 探针用临时 HOME 模拟，不拦截真实安装器 | 需要真实隔离时得配 Docker |

## 五、怎么复现

```bash
pnpm install
pnpm build
pnpm test                       # 54 个用例
pnpm gen:web                    # 重新生成 30 题任务集
pnpm gen:general                # 重新生成 20 题通用任务集
pnpm fetch:skills               # 拉 5 个真实技能包（写 benchmarks/skills.lock.json）

# Tier 0：任何技能包，秒级
node dist/cli.js probe benchmarks/skills/agent-skills --only static-cost

# Tier 1：三臂对照（需要 key 与模型）
UPLIFT_API_KEY=... UPLIFT_MODEL=... \
node dist/cli.js run --taskset web-guidance@1.0 --skill <path> --repeats 3 --jobs 4
```
