## 一、一句话版本（发帖标题、README 徽章、口口相传都用它）

**Every skill package ships a claim. Almost none of them survive a length-matched placebo.**

中文：**每个技能包都宣称自己有用。加上一个等 token 的安慰剂臂之后，几乎没有一个还站得住。**

备选标题（A/B 用，都是 60 字符内，HN 不截断）：

1. `Show HN: A placebo arm for Agent Skills – most skills add nothing`
2. `Show HN: We measured 12 popular Agent Skills; one skill is 52× the token budget`
3. `Show HN: What happens when you run a placebo arm on AI agent skills`

第一标题讲**结论**（让人愤怒或好奇），第二标题讲**具体数字**（可信），第三标题讲**方法**（吸引同行）。
HN 上结论型标题最容易起量，方法型标题最容易吵起来。选哪个看你想要哪种讨论。

## 二、Show HN 正文（英文，可直接贴）

```
I got tired of "this skill gives +27pp" with no way to check it, so I built the arm
that most benchmarks skip: a placebo.

Setup: same model, same task set, same seed, three arms.
  baseline  – no skill
  placebo   – neutral text, token-matched to the skill (±2%)
  treatment – the real skill

uplift = treatment − placebo. Not treatment − baseline.

Two results that changed how I think about skills:

1) The skill that made me build this
   GoogleChrome/modern-web-guidance, 48 tasks, 720 runs, ~$61:
     baseline 73.75% | placebo 73.75% | treatment 71.25%  → uplift −2.50pp, 95%CI [−7.92, +2.50]
   Its own description says "MANDATORY: Execute FIRST for all HTML/CSS tasks".
   The model loaded it in 23% of runs. In the other 77%, "treatment" WAS "baseline" —
   so that −2.5pp is mostly measuring willingness to call a tool, not the skill.

   Force the skill into context (432 more runs) and the same skill flips to +5.56pp,
   with placebo_effect −7.64pp: 9.4k tokens of neutral text costs 7.6 points, the
   skill's content earns back 5.6. Neither number is "the" number; they answer
   different questions.

2) Where a skill actually earns its keep
   I rebuilt tasks so the prompt states the symptom and withholds the API name,
   on APIs the skill actually documents. 5 tasks × 3 arms × 10 repeats:
     baseline 34% | placebo 32% | treatment 68%  → uplift +36pp, 95%CI [+24, +48]
   Length-matched placebo is worth −2pp. The knowledge is worth +36pp.
   That is the whole thesis, measured on a small, deliberately selected block.

And because the cheapest probe needs no model, I ran it on 12 popular packages
(~1.9M stars): karpathy-guidelines is 644 tokens end to end. ECC spends 2,375
tokens just listing its 47 skills. anthropics/skills' claude-api is 526,405 tokens
in a single skill — 52× the budget — while Nutlope/hallmark ships a 113k JSON file
inside the skill directory.

What I do NOT claim: that any specific skill is useless. One task set, one model,
one harness per number. I also published five of my own grader false negatives —
three of them made the skill look worse than it was, and fixing them flipped a
−40pp into +20pp.

Everything is seeded, every run's cost is recorded, and the repo ships the run
databases. If you think a number is wrong, there is an issue template for exactly
that: "challenge a number".
```

**长度**：约 380 词。HN Show 帖的经验区间是 250–500 词，太短像广告、太长没人读完。

## 三、首评（自己发的第一条评论，必须放「诚实」这一侧）

```
Three things that did not survive contact with reality, in case they save you time:

1. Regex graders encode one valid syntax; correct answers have equivalence classes.
   I required showPopover() and rejected the declarative popovertarget. I banned
   insertBefore and rejected a feature-detection fallback that the skill itself
   recommended. Five of these, all in one day, and every single one made the skill
   look worse. Fix: behaviour tests (import the candidate code and run it), and
   never finalise a grader before you've seen what the model actually writes.

2. Putting the API name in the prompt turns the task into transcription.
   Same fixture, prompt with the name removed: baseline 100% → 0%. One word, 100
   percentage points. Half of my original task set was measuring typing.

3. I published a placebo explanation that my own data destroyed. I claimed round 1's
   −4.4pp placebo effect came from injecting neutral text; then I checked by_arm and
   found the placebo arm had never been activated in round 1. It was noise. Corrected
   in the docs, kept the old text visible.

Happy to answer anything about the setup. The metric definitions are in
docs/02-protocol.en.md, and the ablation write-up is docs/16.
```

为什么必须放这段：HN 上「说自己错」比「说自己对」更能换来信任，而且它抢在评论区之前把最锋利的三个攻击点卸掉了。

## 四、X / Twitter 串（6 条，配图用 `docs/assets/hero.png`）

1. 每个 AI 技能包都在宣称自己有用。
   没人跑安慰剂臂。
   我跑了。🧵

2. 三臂设计：无技能 / **等 token 中性文本** / 真技能。
   `uplift = treatment − placebo`，不是减 baseline。
   减 baseline 的那个数，等于把「上下文变长了」也算成技能的功劳。

3. 第一个结果很扫兴：
   GoogleChrome 那个技能，48 题 720 次 run，
   baseline 73.75% · placebo 73.75% · treatment 71.25%
   → **−2.5pp**（CI −7.9 ~ +2.5）
   它自己的描述写着 "MANDATORY: Execute FIRST"，模型只在 **23%** 的运行里真的加载了它。

4. 把那 77% 的运行修掉（强制注入技能正文，再跑 432 次）：
   同一个技能 **+5.56pp**，而安慰剂效应 **−7.64pp**。
   同一份技能，两种激活条件，符号相反。
   两个数都对，它们回答的是两个不同的问题。

5. 真正能证明技能有用的，是我重做的那 5 道题：
   提示词只写症状、不给 API 名，且 API 是技能里真写了的。
   baseline 34% → treatment 68%，**+36pp**，而等量安慰剂只有 **−2pp**。
   **长度不值钱，知识值 36 个点。**

6. 顺带量了 12 个真实技能包（约 190 万 star），零模型调用、几秒钟：
   · karpathy-guidelines 整包 **644** token
   · ECC 47 个技能，**光列菜单 2,375** token
   · claude-api 单技能 **526,405** token = 预算 52 倍
   · hallmark 把 113k 的 JSON 塞在技能目录里
   工具：`npx` 一行，零依赖。仓库在评论里。

## 五、评论区预案（前两小时最关键）

| 会有人说 | 准备好的回答 |
|---|---|
| 「一个模型一个任务集，凭什么下结论」 | 不凭什么。每个数字自己都带 N 与 CI，`docs/15 §七` 有一节叫「证明了什么、没证明什么」。这一轮证明的是**方法可用**（同一条件下能测出 +36pp 且安慰剂 ≈0），不是「某技能没用」 |
| 「+36pp 是你挑的 5 道题」 | 对，而且我写在标题里了。它只在 **forced 激活 + 技能覆盖 ∩ 模型先验缺失** 下成立。榜单口径是 −2.5pp（48 题 auto ITT），两个都贴 |
| 「正则评分器能作弊」 | 已经是被我自己发现五次的东西，现在有 8 道题改成行为测试（把代码 import 进来跑），并有一条测试守着「提示词不许出现答案」 |
| 「技能包作者会不高兴」 | 我们只报可测事实（token、超预算、目录成本、能否干净卸载），不评内容好坏。`docs/17` 里 12 个包没有一个是「坏」，只有「贵在哪」 |
| 「为什么不直接用 SkillsBench」 | 详见 `docs/01`：他们只有 Tier 1（手写题），我们多了 Tier 0 通用探针和三臂对照；两者不冲突，题集可以互相导入 |
| 「安慰剂臂 +50% 成本」 | 是。Tier 0 不需要安慰剂（它出事实不出分数），只有要发 uplift 数字时才跑三臂 |

## 七、一句话不要说的话

- ❌「我们发现某技能没用」。没测过的事不说。
- ❌「行业首个」。`docs/01` 里已经承认 SkillsBench 先做了 Tier 1。
- ❌「+36pp」单独出现。必须带「5 题、forced、CI [+24,+48]」。
- ✅ 「安慰剂臂」「同一模型同一题集」「每个数字带 N 和 CI」「我们改过自己五次」。
